# Как мы работаем

Короткие правила для команды и для агента. План — [docs/PLAN.md](docs/PLAN.md), критерии приёмки — [docs/features.json](docs/features.json).

## Роли

- **Разработчик один — ИИ-агент.** Он пишет весь код, конфигурацию, миграции, прошивки, тесты и документы.
- **Люди не пишут код.** Каждый из пятерых ведёт свой трек: задаёт направление, отвечает на вопросы агента, ревьюит и одобряет PR, делает то, что агент физически не может.

| Трек | Что ревьюит | Что делает руками |
|---|---|---|
| P — платформа и бэкенд | `infra/`, `services/ingest/`, `services/simulator/`, `packages/`, корневые конфиги | команды с `sudo`, Docker, настройки GitHub |
| W — веб и интерфейс | `apps/web/` | проверка интерфейса на телефоне и ноутбуке |
| M — ML | `services/ml/`, `data/manifests/` | запись реальных звуков, проверка метрик |
| H — железо | `firmware/`, `edge/` | подключение датчиков, ESP32 и Raspberry Pi к ноутбуку |
| D — дизайн, QA, питч | `docs/`, дизайн-токены | сертификат на демо-телефоне, репетиции, видео-бэкап |

Кто за каким путём закреплён — в [.github/CODEOWNERS](.github/CODEOWNERS).

## Как ревьюить PR, не программируя (≈ 10 минут)

1. Прочитайте раздел «Что сделано и зачем».
2. Выполните «Как проверить самому за 5 минут». Каталог, команды и адрес указаны точно. Сравните результат с пунктом «что вы должны увидеть».
3. Найдите фичи PR (Fxx) в [docs/features.json](docs/features.json). Пройдитесь по критериям приёмки: каждый ли подтверждён в «Доказательствах»?
4. Откройте 3–5 мест из «Где смотреть в коде». Понятно ли по однострочным пояснениям, что там происходит? Если нет — спросите в комментарии, агент объяснит простыми словами.
5. Прочитайте «Вопросы жюри». Сможете ли вы ответить на них сами?
6. Нажмите **Approve**, если всё сходится. Иначе — **Request changes** с конкретным пунктом.

**Не делайте:**
- не коммитьте правки через веб-интерфейс GitHub («Commit suggestion», редактирование файла);
- не нажимайте **Update branch**.

Такие коммиты созданы не git-идентичностью проекта и не пройдут проверку `commit-hygiene`. Вместо этого оставьте комментарий.

## Ветки, PR и слияние

- `main` всегда в состоянии «можно показывать». Прямые пуши в `main` запрещены.
- На каждый срез — одна ветка и один PR. Имя ветки: `<type>/<Fxx>-<тема>`, например `feat/F08-alert-feed`. В PR ссылки на Fxx, ориентир — до ~400 изменённых строк.
- До вашего ревью PR уже проверил отдельный ревью-агент, который этот код не писал.
- После вашего одобрения и зелёного CI агент сам делает squash-merge и удаляет ветку.
- Одновременно открыто не больше 3 PR. Чем быстрее ревью, тем быстрее работа: пожалуйста, отвечайте на PR своего трека в течение 1–2 часов.
- Только с вашего явного согласия в чате: теги `demo-N`, изменения настроек репозитория, любые необратимые действия.

## Авторство коммитов (жёсткое правило)

- Все коммиты делаются от git-идентичности этого репозитория (`git config user.name` и `user.email`).
- В метаданных git и GitHub нет никаких следов ИИ. Это касается сообщений коммитов, заголовков, описаний и комментариев PR, тегов и релизов. Запрещены:
  - трейлеры соавторства;
  - строки об инструменте, которым «сгенерирован» текст;
  - эмодзи робота;
  - названия ИИ-инструментов.
- Правило проверяется автоматически:
  - git-хуки lefthook: `commit-msg` проверяет сообщение, `pre-push` — все локальные коммиты, которых ещё нет на GitHub;
  - CI-джоб `commit-hygiene` проверяет коммиты PR, его заголовок и описание.
- Ручная проверка: `node scripts/commit-hygiene.mjs unpushed`.
- Пушьте из терминала, а не из графического клиента: хукам нужен Node.js из `~/.local/bin`.

## Языки

- Английский: код, идентификаторы, комментарии, сообщения коммитов, заголовки PR.
- Русский: документация в `docs/`, описания PR, отчёты и запросы агента. README начинается с короткого резюме на английском для международного жюри.

## Как агент просит о помощи

Запросы всегда стоят в самом начале отчёта, одним списком. Для каждого указано:
- чей трек;
- зачем это нужно;
- точные команды или клики;
- в каком каталоге выполнять;
- какой вывод должен получиться;
- как агент проверит результат.

Агент также пишет, чем занят, пока ждёт.
